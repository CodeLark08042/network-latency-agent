## 3. 阶段二：为什么 Tool 要这样拆

任务书要求"Agent 自主决定调用哪个工具"，所以工具边界必须**和人类运维的判断步骤对齐**，而不是按代码模块拆。

最后拆成 4 个：

1. `list_links` —— 先看全部上联链路，建立全局印象（对应"先扫一眼监控大盘"）
2. `get_link_metrics` —— 对可疑链路看详细指标（对应"点进去看曲线"）
3. `compute_queueing_delay` —— 用 M/M/1 算理论排队时延（对应"算一下是不是排队造成的"）
4. `check_device_health` —— 看设备 CPU / 温度 / 错误包（对应"排除硬件故障"）

**关键决策：工具预算硬上限 5 轮放在模型桥接层，而不是放在 Agent 循环外。**
因为小模型（`qwen3.5:0.8b`）会在"证据已经够了"的情况下继续调工具。如果只在循环外限制次数，模型会一直要到被强行打断，报告质量反而更差。放在桥接层后，第 5 轮结束就撤掉 tool schema 并追加一句"预算已用完，立即输出报告"，模型就会自然收尾。这个改动在 `backend/llm_bridge.py` 和 `src/agent.py` 里都能看到。

## 4. 阶段三：Skill 为什么要从 800 行砍到 60 行

第一版把"怎么判断拥塞 / 怎么判断硬件故障 / 报告模板"全塞进一个文件。问题是：

- 每次调用都要把 800 行塞进上下文，小模型上下文本来就紧张；
- 模型看到太多分支描述，反而挑错判断路径。

重构后采用**渐进式披露**：

- `SKILL.md`（约 60 行）：只有元数据 + 判断决策树 + 输出格式硬约束，永远注入；
- `reference.md`：详细的指标阈值、公式推导、案例，**只在需要时**由 `src/skills.py` 加载。

同时把 Skill 做成了**运行时唯一真源**：CLI 和 Web 后端都通过 `src/skills.py` 读同一份 `SKILL.md`，避免"改了文件但代码里还写死一份"的漂移。

效果见 run4：C 组（Agent + Tool + Skill）的 tool correctness 从 B 组的 0.868 提升到 0.934。

## 5. 阶段五：前端风格的讨论过程（老师重点要求）

老师给的 `5-antho-front-design.md` 要求先回答四问，再动手写代码。下面是当时的回答和落地方式。

### 5.1 Purpose（这东西给谁、干什么用）

使用者是**夜班 NOC 工程师**，凌晨三点盯着一面墙的监控，看到一个延迟告警。他不需要"漂亮的宣传页"，他需要**30 秒内判断这条链路要不要现在就动手**。

所以页面第一屏必须是：案例选择 + 一句话告警描述 + 一个能立刻点的按钮。不是 hero 大标题，不是功能介绍。

### 5.2 Tone（什么气质）

**深夜网络运行中心的工业仪器盘**。参照物是机房里的设备面板：深色底、等宽字、直角、明确的刻度与状态灯，而不是 SaaS 落地页。

### 5.3 Constraints（硬约束）

- 零构建：老师要求 Pages 能直接打开，所以不能引入 React/Vite，必须原生 HTML/CSS/JS；
- 源码可读：老师可能直接看 `script.js`，所以不压缩、不混淆、函数用中文注释说明意图；
- 双模式：Pages 上没有 Python，必须支持"无后端也能演示"；
- 中文字体可读：等宽字体只用于数字与标签，正文用 Noto Sans SC。

### 5.4 Differentiation（记住它的那一个点）

**它得像一台正在工作的仪器，而不是一张截图。**
具体做了三件事：

1. 左上角的 `LINK` 指示灯**真的在呼吸**（4s 周期的 box-shadow 脉冲），并且颜色反映后端探测结果：绿色=实时后端、琥珀=静态回放；
2. 顶部一排**五格读数条**（SOURCE / MODEL / TOOL ROUNDS / LLM CALLS / ELAPSED），跑一次调查就真实刷新一次；
3. 调查报告**逐行淡入**（每行 40ms 延迟），模拟日志滚动，让人能看到"它在思考"。

### 5.5 主动排除的方向（也是文档里的 NEVER 清单）

| 被排除的做法 | 为什么不用 |
| --- | --- |
| Inter / Roboto / Arial | 这三个字体是"AI 生成味"最强的信号，且与仪器感无关；改用 Chakra Petch（拉丁标题）+ IBM Plex Mono（数字） |
| 白底 + 紫色渐变 | 5-antho 文档明确列为 AI slop 特征；改用深色仪表盘底 `#0b0e11` |
| 大圆角卡片堆叠 | 仪器面板是直角；全站 `border-radius: 0`，用 1px 描边 + tick 角标划分区域 |
| 居中 hero + 三栏卖点 | 运维工具不需要营销结构；改用左侧固定控制栏 + 右侧工作区 |
| 无意义的 loading 转圈 | 改为"读数条逐格点亮 + 报告逐行淡入"，进度可见而非空转 |

### 5.6 落地核对

逐条对照 `5-antho-front-design.md` 的检查项后，把结论写进了 `docs/02-前端界面设计文档.md` 第 13 节的"设计评审清单"（9 项），包括字体、配色、圆角、动效、reduced-motion 降级、空态/异常态等。

## 6. 阶段六：HLD 里最花时间的一节

写 `docs/03-后端HLD.md` 时，最费劲的不是画架构图，而是**降级链**的定稿。

一开始只想"有 Key 调 DeepSeek，没 Key 报错"，但这样老师如果不配 Key 就完全看不到效果。最终定成三档：

1. 有 Key → 真实调用 DeepSeek，`source=deepseek`；
2. 无 Key → 离线规则判读（`backend/mock_engine.py`），`source=mock`，**并且界面明确标注"非大模型输出"**，不冒充模型结果；
3. 云端调用异常 → 捕获异常，回退到同一套规则判读，并把错误原因带进 warning 展示。

第 3 档是实测出来的：我们故意填了一个假 Key，DeepSeek 返回 `401 Authentication Fails`，页面正确显示黄色横幅并给出规则结论，而不是白屏。

## 7. 阶段七：Pages 只能放静态文件

Pages 不能跑 Python，所以线上的 `docs/` 目录同时承担两个角色：既是前端源码，也是 Pages 站点根目录。后端启动时用 `app.mount("/", StaticFiles(directory="docs", html=True))` 把前端挂上去，注意**挂在 API 路由之后**，保证 `/api/*` 优先匹配。

前端因此要写两套启动路径：`bootLive()` 探测 `/api/health` 成功则走实时，失败则 `bootStatic()` 回放 `docs/demo-data.json`（里面是从 run4 真实 trace 抽出来的 5 个案例）。线上横幅会写"未检测到后端：回放 results/repeat/run4 中保存的真实 trace"，避免让人误以为是此刻现算的。

## 8. 遇到的真实问题与解决（问题清单）

| # | 现象 | 定位 | 解法 |
| --- | --- | --- | --- |
| 1 | `cannot import name 'CacheableResult' from 'mcp.types'` | 后端准备用 litellm 转发 DeepSeek，但 litellm 依赖的 `mcp` 版本与本地环境冲突 | 放弃 litellm，改用 `openai` SDK 直连 `https://api.deepseek.com`（OpenAI 兼容），依赖从 5 个减到 1 个 |
| 2 | 假 Key 也能返回正常结果 | 一开始的 try/except 把异常吞掉了 | 改为：捕获异常后回退规则判读，但**必须把异常原文带进 warning**；随后用假 Key 验证确实打印出 401，证明请求真的到了 DeepSeek |
| 3 | `git push` 到 GitHub 超时 | 本机代理只对浏览器生效，Git 不走代理 | 只对本仓库配置 `http.proxy=http://127.0.0.1:7890`，不改全局配置 |
| 4 | 空仓库首次推 `main` 被拒（HTTP 500） | GitHub 对完全空的仓库创建默认分支 ref 时出错 | 先推一个临时分支 `dev` 建出 ref，再推 `main`；后续需在网页把默认分支改回 `main` 并删除 `dev` |
| 5 | README 表格错行 | 单元格里写了 `run2|run3|run4/`，竖线被当成列分隔符 | 改成 `results/repeat/`（run2 / run3 / run4） |
| 6 | `Compress-Archive` 返回 exit code 1 | 压缩进度流写入 stderr，导致退出码被误判为失败 | 改用 `ZipFile::OpenRead` 直接读条目数校验产物（122 条目），不依赖退出码 |
| 7 | 小模型偶尔不收敛、反复调工具 | Agent 循环没有硬边界 | 预算放桥接层，超预算撤 tool schema + 追加收尾指令（见第 3 节） |

## 9. 我们和 AI 协作的方式

这门课基本是两个人加 AI 结对。AI 输出的东西不当结论用，习惯是当场验一遍。

比如后端换 SDK 那次，代码看着没问题，我们还是拿假 Key 打了一发请求，看到 `401 Authentication Fails` 才算确认请求真的发出去了。说"效果好"也得有数据，run4 的三组指标是脚本跑出来的 CSV，不是估的。文档里的架构要和代码对得上，写完 HLD 我们逐条回查了 `backend/main.py` 的路由和降级分支，顺手发现 `_ACTIVE_SCENARIO` 这个全局变量在并发下会串场景，写进 HLD 第 13 节，没藏着。

## 11. 反思：如果继续做

1. **并发缺陷**：`_ACTIVE_SCENARIO` 是全局变量，多人同时调查会串场景。正解是换成 `contextvars.ContextVar`，HLD 里已写明改法，但 MVP 阶段没做。
2. **Skill 缺少回归测试**：目前靠人工看 run4 的报告质量，没有"改了 SKILL.md 是否变差"的自动化断言。
3. **前端在移动端只是"能用"**：880px 以下会变成上下堆叠，但没有针对触屏重做交互（长按、滑动切 tab）。
4. **成本还没有实测**：报告里的成本估算是按 token 单价推算的，没有用真实账单核对。
