# 延迟调查参考手册

本文件是 `SKILL.md` 的第三层内容：只在需要公式推导、量级核对或排查具体误判时查阅。

## 1. 四类时延

总延迟 = 传播延迟 + 传输延迟 + 排队延迟 + 处理延迟

| 类型 | 公式 | 典型量级 | 决定因素 |
| --- | --- | --- | --- |
| 传播 d_prop | 距离 / 传播速度（光纤中约 2×10⁸ m/s，即 5 μs/km） | 每 100 km 约 0.5 ms | 物理距离、介质 |
| 传输 d_trans | 数据包位数 / 带宽 | 1500 B @ 1 Gbps 约 12 μs | 带宽、包大小 |
| 排队 d_queue | 由利用率和到达过程决定 | 0 ~ 数百 ms | 利用率、突发程度、缓冲区 |
| 处理 d_proc | 查表、校验、调度 | 0.1 ~ 1 ms | 设备性能、规则数量 |

量级核对：若分解结果中传播延迟达到几十毫秒，先检查链路长度字段是否单位错误，而不是直接采信。

## 2. M/M/1 排队模型

适用前提：泊松到达、指数服务时间、单队列单服务台、稳态（ρ < 1）。

- 利用率 ρ = λ / μ
- 平均系统内包数 L = ρ / (1 − ρ)
- 平均队列长度 Lq = ρ² / (1 − ρ)
- 平均系统时间 W = 1 / (μ − λ) = L / λ
- 平均排队时间 Wq = ρ / (μ(1 − ρ)) = Lq / λ

服务率换算：μ = 带宽(bps) / (平均包长(byte) × 8)。

例：1 Gbps 链路、800 B 包，μ = 10⁹ / 6400 ≈ 156250 pps。

关键性质：

- ρ < 0.5 时排队延迟可忽略；
- ρ > 0.7 时排队延迟开始显著上升；
- ρ → 1 时趋于无穷；
- ρ ≥ 1 时不存在稳态，模型失效。

**工程注意**：分析实测链路时，ρ 应取监控上报的**实测利用率**，而不是"到达率 ÷ 理论带宽服务率"。后者会把一条实际拥塞的链路算成 ρ ≈ 0.06，得出"无拥塞"的错误结论。

## 3. 常见误判清单

1. **RTT 升高就是拥塞。** 路由变更、硬件重传、跨运营商绕行都会抬高 RTT。必须同时看利用率、队列、丢包。
2. **利用率高就是拥塞。** 利用率 85% 但队列浅、无丢包，可能只是短时高峰，不构成持续拥塞。
3. **忽略路径变化。** 每段链路都正常，端到端仍然变慢，通常是流量切到了更长的备用路径。
4. **把 M/M/1 外推到 ρ ≥ 1。** 此时算出的负值或无穷大没有物理意义，应报告过载。
5. **只看一条链路。** 端到端时延是路径上各段之和，单段正常不能代表整条路径正常。
6. **把理论值当实测值。** 理论排队时延只描述平均行为，不含 TCP 重传与缓冲区膨胀，通常远小于实测；差异要用"还有其它因素"解释，不能宣称两者吻合。

## 4. 证据解读参考

| 现象组合 | 倾向的解释 | 还需补充的证据 |
| --- | --- | --- |
| 利用率 > 80%，丢包 > 0.1%，队列数百 | 拥塞导致缓冲溢出 | 峰值队列、流量趋势 |
| 利用率 < 50%，丢包 > 1%，RTT 高 | 硬件/误码，重传放大时延 | 接口错误计数、光功率 |
| 各段利用率正常，RTT 增加且传播延迟占比升高 | 路由变更、路径变长 | 路由表前后对比、traceroute |
| 关键字段为 null | 监控缺失，无法定位 | 补采数据 |

区分"拥塞"与"硬件故障"的核心是**利用率与丢包是否同时异常**；区分"拥塞"与"路由变更"的核心是**传播时延占比是否升高**。
